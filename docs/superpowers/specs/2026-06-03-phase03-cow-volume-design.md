# Фаза 03 — COW Volume Manager (дизайн)

**Дата:** 2026-06-03
**Дорожная карта:** `docs/superpowers/plans/2026-06-02-xboot-roadmap.md` (Фаза 03)
**Базовая спека:** `docs/superpowers/specs/2026-06-02-xboot-diskless-boot-engine-design.md` (§4 логика COW, §6 ошибки)
**Статус:** утверждён; следующий шаг — имплементационный план.

## Цель

Виртуальный том клиента = read-only мастер (`BackingStore` из Фазы 02) + volatile
writeback-оверлей с copy-on-write. `Volume` платформо-независим, не знает про iSCSI —
это «виртуальный диск с COW», который Фаза 05 будет дёргать командами READ/WRITE.

Правило COW из спеки §4:

```
READ блока N:  есть в оверлее? → отдать из оверлея; иначе → прочитать из мастера
WRITE блока N: всегда в оверлей; мастер НИКОГДА не меняется
```

(RAM-кэш мастера между оверлеем и мастером добавит Фаза 04 — здесь read-path ходит
прямо в мастер.)

## Ключевые решения (из брейншторма)

1. **Оверлей за трейтом `OverlayStore`.** Сейчас — RAM-реализация (`RwLock<HashMap>`).
   Дисковая (sparse-файл на NVMe) добавится позже за тем же трейтом. Хранилище оверлея
   изолировано от логики `Volume`.
2. **COW-единица — фиксированный блок 4 KiB**, частичные записи через read-modify-write.
   `Volume::read_at/write_at` принимают произвольные байтовые диапазоны (как `BackingStore`
   плюс запись). Это даёт побайтовую корректность против плоской байтовой модели — основа
   property-теста.
3. **Везде `&self`, внутренняя мутабельность.** `Volume: Send + Sync`, шарится как
   `Arc<Volume>` между async-задачами без обёрток. Готово к конкурентному инициатору
   Фазы 05 без переделки интерфейса. Доступ к блокам — копированием (а не возврат `&[u8]`),
   чтобы не упираться в лайфтаймы блокировки.

## Архитектура и размещение

Новый модуль `crates/xboot-core/src/volume/` рядом со `storage/`:

```
volume/
  mod.rs       — Volume + публичный API (read_at/write_at/reset), константа BLOCK
  overlay.rs   — трейт OverlayStore + RamOverlay (RwLock<HashMap<u64, Box<[u8]>>>)
```

`BLOCK = 4096`. Виртуальный размер тома = размер мастера (оверлей не расширяет диск).
Мастер берётся как `Box<dyn BackingStore>`; у трейта нет write-метода, поэтому путь
записи в мастер физически отсутствует (структурная гарантия §6).

## Компоненты

### `OverlayStore` (трейт, `Send + Sync`)

Хранит перезаписанные блоки; доступ по копированию (дружелюбно к блокировке):

```rust
trait OverlayStore: Send + Sync {
    /// true = блок есть, buf заполнен из оверлея; false = блока нет.
    /// buf.len() = фактическая длина блока (на хвостовом блоке < BLOCK).
    fn read_block(&self, blk: u64, buf: &mut [u8]) -> bool;
    /// Сохранить/перезаписать блок целиком.
    fn write_block(&self, blk: u64, data: &[u8]);
    /// Выбросить всё содержимое (volatile «ребут»).
    fn reset(&self);
}
```

### `RamOverlay`

`RwLock<HashMap<u64, Box<[u8]>>>`. Ключ — индекс блока, значение — данные блока
(на хвостовом блоке длина может быть < 4 KiB).

### `Volume`

Владеет `Box<dyn BackingStore>` (мастер, RO) + `Box<dyn OverlayStore>`:

```rust
impl Volume {
    fn new(master: Box<dyn BackingStore>, overlay: Box<dyn OverlayStore>) -> Self;
    fn size_bytes(&self) -> u64;                              // = master.size_bytes()
    fn read_at(&self, offset: u64, buf: &mut [u8]) -> io::Result<()>;
    fn write_at(&self, offset: u64, buf: &[u8]) -> io::Result<()>;
    fn reset(&self);                                          // overlay.reset()
}
```

## Поток данных

Размер блока с учётом хвоста: `block_len(blk) = min(BLOCK, size_bytes - blk*BLOCK)`.

### `read_at(offset, buf)`

Проход по 4 KiB блокам, пересекаемым диапазоном `[offset, offset+buf.len())`:

- для каждого блока: `overlay.read_block(blk, …)` → если `true`, отдаём нужный срез из
  оверлея; иначе читаем соответствующий кусок из мастера (`master.read_at`).
- частичные края блока (начало/конец диапазона) обрабатываются срезами, как в `read_units`.

### `write_at(offset, buf)`

Проход по блокам:

- **блок покрыт диапазоном полностью** → `overlay.write_block(blk, срез)`.
- **частично, блока ещё нет в оверлее** → завести буфер длиной `block_len(blk)`,
  прочитать его из мастера (read-modify-write), наложить байты записи,
  `overlay.write_block`.
- **частично, блок уже в оверлее** → `read_block` в буфер, наложить байты, записать
  обратно.

RMW и хранение используют фактическую длину блока, а не всегда 4096.

### Замечание про переиспользование

`read_units` из `storage/blockmap.rs` заточен под **один** физический источник, а здесь
источников два (оверлей + мастер) плюс RMW на записи. Поэтому будет **свой** проход по
блокам в том же стиле, а не прямой вызов `read_units`. Обобщать `read_units` под два
источника не будем — это лишняя связанность.

## Обработка ошибок / граничные случаи

- `read_at`/`write_at` за пределами `size_bytes` → `io::Error(InvalidData)` (как в
  `read_units`), без паники.
- Чтение/запись нулевой длины → no-op, `Ok`.
- Мастер никогда не открывается на запись (у `BackingStore` нет write-метода).
- `reset()` после записей → последующие чтения возвращают чистый мастер (volatile).

## Тестирование (TDD, спека §7)

- **Юнит-тесты** на каждую ветку read/write: hit из оверлея, miss → master, полный блок,
  частичный новый (RMW), частичный существующий, спан нескольких блоков, хвостовой
  неполный блок, выход за границу, нулевая длина.
- **proptest (ядро):** случайная последовательность read/write по `Volume` == эталонная
  in-memory модель (плоский `Vec<u8>`, инициализированный содержимым мастера). Математически
  фиксирует корректность COW.
- **Lifecycle-тест:** запись → `reset()` («ребут») → чтение возвращает мастер; мастер
  байт-в-байт не изменился.
- **Изоляция:** два `Volume` на общем `Arc` мастере с разными оверлеями — запись в один
  не видна в другом.
- **Конкурентность:** лёгкий смоук с `Arc<Volume>` (параллельные read/write не паникуют,
  не портят данные). Полноценная нагрузка — Фаза 05.

## Вне scope Фазы 03 (YAGNI)

- RAM-кэш мастера (Фаза 04) — read-path пока ходит прямо в мастер.
- Дисковая (NVMe) реализация `OverlayStore` — позже за тем же трейтом.
- Персистентный writeback — только volatile.
- iSCSI / SCSI — Фаза 05.

## Готово, когда

Мастер доказуемо неизменен, запись изолирована в оверлее, `reset` работает;
property-инвариант COW зелёный; `cargo fmt --check`, `cargo clippy --all-targets
--all-features -- -D warnings`, `cargo test --all` — зелёные.
